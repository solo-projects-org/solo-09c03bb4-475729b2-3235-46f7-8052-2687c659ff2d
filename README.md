# 地方志年鉴勘误凭据系统

地方志编辑向年鉴发出勘误时，需要附上读者能从原书核对的依据。本系统接收
**最多 4×4 的区县作物面积 CSV**（格值为至多四位的非负整数 0..9999），
由编辑录入**原书核准的行、列合计**，并指定一格及其**拟改值**；
系统在“OCR 至多两格、每格只误识一位十进制数字”的假设下，找出
**条目最少的一组合计**来证明拟改值，并把原值、拟改值与引用合计固化为
SQLite 凭据。被引用合计一旦修改，凭据立即失效。

## 判定规则（业务语义）

1. **误识模型**：OCR 表与原书真表至多有两个格不同；每个不同的格恰好只错
   一位十进制数字，位数不变（多位数首位不能变成 0；0 为一位数，可误识为 1..9）。
2. **引用合计须有解**：一组合计至少存在一张符合误识模型的候选原表同时满足。
3. **无反例**：满足该组合计的**每张**候选原表，在指定格上都必须取拟改值。
4. **最少条目**：合计子集按 1 条、2 条…… 的顺序枚举，返回第一个同时满足
   规则 2、3 的子集（同规模下按条目顺序取第一个，保证结果稳定）。
5. **矛盾与反例**：
   - 全份合计没有任何候选表可满足 → 报告**矛盾**及原因（行列总和不等 /
     超出 0..9999 格值界 / 合计在一般整数表下可行但超出误识模型）；
   - 任何合计子集都无法钉住拟改值 → 报告**反例**，附一张满足全部已录入合计、
     但目标格不取拟改值的候选原表。矛盾与反例均**不生成凭据**。
6. **凭据与失效**：凭据保存目标格原值、拟改值及引用合计的快照值；
   被引用合计被修改（值确实变化）时，相关有效凭据在**同一数据库事务内**
   立即标记失效；未被引用合计的更正不影响任何凭据；以相同值重复保存不算修改。
7. **馆方回执**：在数据集页按馆登记“馆名 + 馆方入库批次号 + 当前采用的全部
   凭据号”。凭据须属于本表，已失效的也可登记；同一格只能报一个采用值；
   空名单表示该馆已撤下全部勘误。各馆按本表的批次号**独立**更新：
   迟到的旧批次不得替换当前回执；当前批次重送同一组凭据沿用原回执，
   换了内容则拒收；任何登记失败都回滚，原回执保持不变。
8. **回查清单**：登记失败/合计更正后，编辑可查看逐馆的“回查清单”，列出需
   回查的格、采用值与所报凭据号。判定无需回查的条件是：**同表、同格、同值
   仍有一份有效凭据，且该凭据的引用合计与现值全部相符**。保存合计更正时
   **不遍历**任何回执；清单在读取时于**单一已提交状态**内同时读取回执、
   凭据状态与现行合计，因此不会出现“回执与依据来自不同版本”的错配。

## 技术实现要点

- 候选枚举：无错（1 张）、一格一位错、两格各一位错，去重后 4×4 约 14.8 万张；
- 合计索引：`合计条目 → 取值 → 候选 id 集合`，子集可行性用集合交计算；
- 矛盾细分：行列总和直检 + Dinic 最大流判断 0..9999 有界整数表可行性；
- 持久化：SQLite（外键级联、事务化失效），六张表
  `datasets / margins / vouchers / voucher_margins / receipts / receipt_vouchers`；
- Web：Flask 3 + gunicorn（单 worker + 线程，适配 CPU/内存特征）。

## 用 Docker Compose 启动

```bash
docker compose up --build
# 浏览器打开 http://localhost:5000
```

- 数据保存在命名卷 `errata_data`（容器内 `/data/errata.db`）；
- 生产环境请把 `ERRATA_SECRET_KEY` 改成固定随机串；
- 健康检查内置在 compose 中，`docker compose ps` 可查看健康状态。

## 本地直接运行（不用 Docker）

```bash
python -m venv .venv && . .venv/bin/activate
pip install -r requirements.txt
# 开发服务器
ERRATA_DB_PATH=./data/errata.db flask --app errata_app.app run --debug
# 或 gunicorn
gunicorn --bind 0.0.0.0:5000 --workers 1 --threads 4 errata_app.app:app
```

## 使用流程

1. 首页上传 CSV（或粘贴文本 / 一键载入样例），每格 0..9999、最多 4×4；
2. 在数据集页录入原书核准的行、列合计（留空表示该条未录入，OCR 自带和仅作参考）；
3. 指定目标格（1 基行列号）与拟改值，提交分析；
4. 证明成立 → 自动生成凭据，可在“勘误凭据”页查看、打印，凭据含引用快照；
5. 后续修改合计：被引用合计变动会使对应凭据立即失效并在页面红字提示；
6. 在数据集页登记馆方回执（馆名、批次号、勾选当前采用的凭据号），
   再用“回查清单”查看哪些馆的采用值已失去有效依据、需要回查。

样例数据、录入数值与预期截图级结论见
[`errata_app/samples/README.md`](errata_app/samples/README.md)。

## 已知边界与待补事项

- 4×4 全量分析约 1.7 秒、峰值内存约 180 MB（单进程实测），故 gunicorn
  固定单 worker；并发分析请求会在线程下串行占用 CPU，超大用户量需加任务队列；
- 合计仅支持非负整数录入（上限 99,999,999）；负数、分数、带单位文本按输入错误拒绝；
- 误识模型固定为“≤2 格、每格恰好 1 位十进制数字”，若年鉴业务需要放宽到
  多位/更多格，需在 `solver.enumerate_candidates` 中扩展枚举参数；
- 当前未做用户登录与操作审计（合计修改历史仅保留快照对比，未提供时间线页面），
  多编辑协同场景建议补鉴权与审计日志；
- 凭据页适合浏览器打印，尚未导出 PDF/盖章版式。
